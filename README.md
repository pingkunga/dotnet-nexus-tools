# dotnet-nexus-tools

A .NET 10 command-line tool for Sonatype Nexus. It can count components across repositories, list components and assets from a single repository, and optionally bulk-delete components from a JSON export.

## Features

- Count components per repository, optionally filtered by repository type and format.
- Process repositories concurrently with a configurable concurrency limit.
- Write JSON results incrementally and generate an optional HTML report.
- List components or assets from a single repository with client-side sorting, limiting, and regex filtering.
- Perform bulk deletion in dry-run mode or execute deletions with `--force`.

## Requirements

- .NET 10 SDK
- Access to a Sonatype Nexus instance with the REST API enabled
- `NEXUS_USERNAME` and `NEXUS_PASSWORD` environment variables

## Build, pack, and install

### Build the project

```powershell
dotnet build
```

### Pack as a .NET tool

```powershell
dotnet pack -c Release
```

This creates a NuGet package such as:

```text
bin\Release\Nexus.Tool.1.0.7.nupkg
```

### Install from the local package

```powershell
dotnet tool install --tool-path .\tools Nexus.Tool --add-source .\bin\Release --version 1.0.7
```

### Run the installed tool

```powershell
.\tools\nexus-tool.exe --help
```

After installation, the command name is:

```text
nexus-tool
```

## Configuration

Set your Nexus credentials before running the tool:

```powershell
$env:NEXUS_USERNAME = "your-username"
$env:NEXUS_PASSWORD = "your-password"
```

## Usage

```text
nexus-tool count --url <nexus-api-url> [--type <repo-type>] [--format <repo-format>] [--concurrency <count>] [--output-dir <directory>] [--output <file>] [--html]
nexus-tool list-components --url <nexus-api-url> --repository <repo-name> [--sort-by <name|version|age|last-modified|last-downloaded>] [--order <asc|desc>] [--limit <count>] [--output <file>] [--output-dir <directory>] [--html] [--name-pattern <regex>] [--version-pattern <regex>]
nexus-tool list-assets --url <nexus-api-url> --repository <repo-name> [--sort-by <name|version|age|last-modified|last-downloaded>] [--order <asc|desc>] [--limit <count>] [--output <file>] [--output-dir <directory>] [--html]
nexus-tool delete-components --url <nexus-api-url> --input <file> [--force] [--concurrency <count>]
```

### Commands

- `count`: Count components by repository. The bare command without a subcommand behaves the same way.
- `list-components`: List components in a repository with metadata and optional filtering.
- `list-assets`: List assets in a repository with metadata.
- `delete-components`: Bulk delete components from a JSON input file generated by `list-components`.

### Common options

- `--url`: Required. Base URL for the Nexus REST API.
- `-h`, `--help`: Show help.
- `-v`, `--version`: Show version information.

### Count options

- `--type`: Optional. Filter repositories by type.
- `--format`: Optional. Filter repositories by format.
- `--concurrency`: Optional. Maximum number of repositories processed concurrently. Default: `10`.
- `--output-dir`: Optional. Directory for the output JSON file. Default: current directory.
- `--output`: Optional. Full output path for the JSON file.
- `--html`: Optional. Generate an HTML report next to the JSON output.

### List options

- `--repository`: Required. Repository name to inspect.
- `--sort-by`: Optional. Sort key. Supported values: `name`, `version`, `age`, `last-modified`, `last-downloaded`. Default: `name`.
- `--order`: Optional. Sort order. Supported values: `asc`, `desc`. Default: `desc`.
- `--limit`: Optional. Maximum number of rows to return after sorting.
- `--output`: Optional. Full output path for the JSON file.
- `--output-dir`: Optional. Directory to use when `--output` is not supplied.
- `--html`: Optional. Generate an HTML report next to the JSON output.
- `--name-pattern`: Optional. Regex pattern to filter component names client-side.
- `--version-pattern`: Optional. Regex pattern to filter component versions client-side.

### Delete options

- `--input`: Required. Path to the JSON file containing components to delete.
- `--force`: Optional. Actually execute deletion. If omitted, the tool runs in dry-run mode.
- `--concurrency`: Optional. Concurrent deletion requests. Default: `2`.

## Examples

### Count all repositories

```powershell
dotnet run -- count --url https://nexus.example.com/service/rest/v1
```

### Count only hosted NuGet repositories

```powershell
dotnet run -- count --url https://nexus.example.com/service/rest/v1 --type hosted --format nuget --output-dir .\out
```

### List components from a repository

```powershell
dotnet run -- list-components --url https://nexus.example.com/service/rest/v1 --repository maven-public --limit 50 --output .\maven-public_components.json
```

### Filter components by regex

```powershell
dotnet run -- list-components --url https://nexus.example.com/service/rest/v1 --repository maven-public --name-pattern "^spring" --version-pattern "^5\."
```

### Generate an HTML report

```powershell
dotnet run -- count --url https://nexus.example.com/service/rest/v1 --html
```

### Dry run deletion

```powershell
dotnet run -- delete-components --url https://nexus.example.com/service/rest/v1 --input .\to_delete.json
```

### Execute deletion

```powershell
dotnet run -- delete-components --url https://nexus.example.com/service/rest/v1 --input .\to_delete.json --force
```

## Output behavior

- The count command writes a default file named `{RepositoryType or RepoTypeAll}_{RepositoryFormat or FormatAll}_components.json`.
- `list-components` writes `<repository>_components.json` by default.
- `list-assets` writes `<repository>_assets.json` by default.
- If `--output` is provided, that exact path is used. Otherwise the tool writes to `--output-dir` or the current directory.
- `--html` creates a sibling `.html` file next to the JSON output.

## Notes

- The tool fails fast if `NEXUS_USERNAME` or `NEXUS_PASSWORD` is not set.
- The `--url` value should point to the Nexus REST API base URL, typically ending with `service/rest/v1`.
- Deletion is safe by default. Use `--force` only when you are ready to delete the selected components.
